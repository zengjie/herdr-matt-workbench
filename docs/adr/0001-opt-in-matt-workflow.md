# Matt 工作流按工作区显式启用

用户同时使用 Matt 和其他开发方式。首版只增强明确启用 Matt 的 Workspace，其他 Workspace 保留原有开发方式，不为它们启动本项目的对话 Agent 或调度。通用 Agent 工作台的范围不包含在本次决定中，以控制首版复杂度。

Workspace 以 Herdr Space 为选择入口，并明确绑定固定工作目录。终端临时改变目录不改变工作流；同一仓库的不同 worktree 可以选择不同工作流，不能把配置提升为全仓库开关。Effort 仍是围绕目标组织的工作集合，不等同于 Workspace。

Herdr 的视觉 layout 属于整个窗口，未提供原生 per-Space 命名 layout 绑定。保留原工作台作为默认，由用户显式进入与退出 Matt 工作台，不根据 Space 选择或焦点变化自动替换整个窗口布局。Matt 增强仅作用于明确启用的 Workspace，原工作台提供可返回的入口。

有运行中任务时，停用 Matt 先停止新增派工，保留 Agent、工作目录和记录，进入 Draining；已有工作处理完毕后完成停用。停用不直接杀进程或删除现场。仅切换 Space 不等于停用。

同一固定工作目录同时只有一个 Matt 调度入口；其他 Space 重复启用时定位到已有入口。Matt 创建的 Worker worktree 归属原 Effort，不自动建立另一套 CoS。

在 Matt 窗口中选择非 Matt Space 时，显示普通终端并隐藏 Matt 专属面板，保留返回原工作台的入口；不自动启用 Matt 或弹出配置向导。

收尾期间允许现有任务的验证、返修、人工验收和已授权集成，不启动后续 Ticket。用户可以选择“暂停并保留现场”，或“取消停用，恢复 Matt”。

重新启用时保留未完成任务、反馈和验收记录，先核对 Agent、工作目录与实际产物，再允许继续工作；不自动重新派工，旧验收不自动适用于当前版本。

Space 改名不影响绑定。删除后重建 Space、改绑目录或目录失效时，暂停受影响的调度，由用户明确关联原工作；已有任务不随目录变更自动搬迁。

用户处于普通 Space 时，Matt 待处理事项只通过汇总标记提示，点击后回到对应 Matt 工作区；不抢焦点、不切换布局、不向正在输入的对话注入通知。详细问题与操作保留在原任务中。

上述决定由用户在 grill-with-docs 第一至四轮确认。用户随后要求更新 Spec 和原型，确认按此整体设计推进。

对应行为同步到实施 Spec 与 E 原型；尚未拆 Implementation Tickets。
