# Herdr 统一工作区：当前设计基线

v0.4 · 2026-11-04 · 可交互原型，真实运行器与 Herdr mods 尚未接入。

本基线收敛此前的布局、人机交互和角色选择设计。主原型为 `matt-workbench-prototype.html?variant=E`；A–D 保留为历史比较，并非需要用户选择的五种日常模式。

## 产品行为与范围

在明确启用 Matt 的工作区中，用户有一个专门对话 Agent。它查阅共同记录，将诉求转换为指向明确工作项和运行的请求。CoS 仅拥有调度职责；采用 implement-spec 时继续由它安排执行和集成。Worker 执行具体行为切片；审阅和集成维持独立职责。

日常界面只有对话、任务、结果三个入口，共享当前工作项、运行、约束、请求和代码证据。只读定位方案是早期方案；当前目标已包含受控执行，因此正式实现需要本地操作通道和持久记录。原型仍只模拟，不会执行命令、写 tracker、调用模型或修改本机 Herdr。

首个真实接入范围：本机、单仓库、单 Effort。原型展示第二个轻量 Effort，用来验证插单后恢复草稿与阅读位置；这不代表已完成跨仓库或多机能力。

## 工作流按工作区启用

以 [ADR 0001](../adr/0001-opt-in-matt-workflow.md) 为准：Workspace 绑定 Space 与固定工作目录，Effort 是其中的目标工作集合。非 Matt 工作区保留原开发方式，不启动本项目的 Agent。终端 cd 不改变绑定；同仓库不同 worktree 可独立选择。

窗口默认保留原工作台，用户显式进入、退出 Matt layout。选择 Space 不自动换 layout；Matt 窗口中的普通 Space 显示终端并隐藏专属面板。后台人工待办只汇总提示，不抢焦点或注入输入。同目录重复启用定位原入口，Worker worktree 归属原 Effort。

停用先收尾，停止后续 Ticket 派工；允许现有任务验证、返修、验收与已授权集成。用户可取消停用，或请求暂停并在确认后保留现场。重新启用先核对再明确继续。改名保留绑定，重建 Space、改绑或目录失效须明确关联、核对，不自动搬迁工作。

## 简单 UI 的规则

- 首页说明正在推进什么、下一步需要用户做什么。需要人判断的决策、验收、异常优先；普通进展不累计为人工待办。
- 主区只显示当前阅读对象。运行编号、工作目录、回执、日志、代码细节按需展开；不常驻第三列仪表盘。
- 对话入口在三个视图中保留，用户草稿、焦点和选区不受通知影响。长回复期间的新输入排队，后台事件单独记录。
- 阅读选择、讨论对象、操作目标分别绑定。点击任务不改变发送消息的对象；纠偏、验收和交接按钮明确展示目标。
- 小任务直接启动一个 Worker；复杂后才拆分。模型配置收进工作设置，沿用默认即可。
- 角色配置草稿按工作和作用域保留。保存只改变后续启动配置；实际运行配置独立记录。换运行器必须明确交接。
- 桌面显示项目导航，手机改用项目选择器。抽屉可关闭、支持 Escape 和键盘焦点循环。
- 原型的模拟回执和故障按钮统一放在折叠的“演练控件”，不作为正式产品操作。

## 同一状态来源

工作集合包含目标、来源指针、完成条件和共同基线。工作项包含依赖、唯一有效运行认领、实际配置、任务目录与环境、约束版本、结果版本、审阅与反馈。

任务状态按实际证据转换：

```text
可开始 → 请求启动 → 已确认执行 → 结果返回 → 人工验收 → 待集成
                                              ↓
                                          当前基线候选验证 → 已集成
结果返回 → 要求修改 → 原会话返修 → 新结果返回 → 重新验收
```

只有确有必要的行为设置人工 gate。原型故意把验收和集成拆开以暴露边界；正式版由 CoS 自动推进已获授权的后续操作，无需让用户逐个确认内部步骤。

“运行器 done”“Agent 读取事件”“人工通过”“集成通过”是四种不同事实。前置任务必须满足本项目声明的完成条件才能放行下游；此原型采用“已集成”。

## 纠偏和交接

```text
用户说明变更 → 确认对象与影响 → 请求暂停 → 确认暂停
→ 保存新约束 → Agent 确认采用 → 继续原会话
→ 新结果 → 复验通过 → 关闭纠偏
```

无关任务继续。受影响的未合入结果失去旧验收资格；不能靠重新点按钮绕过新约束。默认继续原 Agent，保持运行编号和现场；仅在用户明确选择时交接。旧运行保持暂停记录，不能覆盖为新运行。暂停只确认 Agent 轮次，预览或子进程需单独查询，不把它描述为全部外部动作已停止。

原型的影响集合为目标和直接依赖，适用于 A/B → C 的演练图。真实调度者必须根据 ticket 依赖图和已保存约束计算完整影响范围；已经集成的跨任务约定变更应新增修复工作项，不能倒退已有提交事实。

## 验收和返修

结果绑定 repo、worktree、base、head/dirty snapshot、预览环境与数据、自动验证命令和输出，以及固定版本的 Standards、Spec 独立报告。

主操作放在结果顶部：通过、要求修改、稍后验收。反馈保存原版本、位置、预期与实际表现。返修继续原会话，生成新版本；新版本复验后才能关闭反馈。代码或约束变化会清除旧验收资格。测试通过不能取代用户验收，也不能证明已经满足新约束。

已验收的结果在当前共同基线上生成候选，验证通过后才推进共同基线。候选失效或失败时，保留原基线、保持下游等待。正式实现需要真实 git/diff/预览/测试/CI 证据；原型中的页面、命令、报告和版本均为 fixture。

完成条件按项目约定。本轮演练采用本地人工验收与集成验证；PR、CI、部署尚未接入，不能把本地完成描述为已发布。

## 操作通道与恢复契约

| 所有者 | 负责的事实 |
|---|---|
| Herdr layout/mod | 用户草稿、阅读位置、目标选择、证据显示、原生终端入口 |
| 操作桥 | 请求持久记录、传递、回执、运行器连接、恢复查询与重复请求处理 |
| 唯一 CoS / implement-spec | 任务认领、依赖放行、约束采用、执行协调、集成顺序 |
| git / tracker / 验证器 | 各自权威的版本、任务及检查结果 |
| 用户 | 决策和必要的人工验收 |

正式实现由长期运行的本地操作进程承载连接；mod 发送短请求和读取投影，不在 30 秒 exec 或重绘内持有长期会话。操作桥不另建调度策略。

操作记录至少带上 Effort、工作项、run、request、操作类型、负载摘要和约束/代码版本。发送前先记录请求；回执与完成分别记录。执行侧基于同一 request 去重，并核对该 work item 的唯一认领。

重启从持久记录恢复 UI，不根据聊天记忆重造任务。重连先查询仍未确认的原请求；有实际回执则采用，没有则保留未知，重试沿用原编号。运行器无法可靠去重的操作不得自动重试；先核对进程、提交或外部对象。

写入采用单写者或版本校验，避免使用 shared 的 last-write-wins 充当任务锁。持久化载体及运行器生命周期仍需真实接入验证，不在 HTML 原型里暗示已实现。

额度不足、网络中断、检查失败分别保留原因、原会话和恢复入口。重连后普通事件“Agent 已读取”不清除仍待用户回答的决策或验收。

## 当前原型覆盖与验证边界

E 的纯状态模块 `UnifiedModel` 与 UI 分离，三个视图读取同一个模型。`unifiedDemo` 提供内存快照与模拟操作入口。六个引导演练：工作区启用与恢复、并行纠偏、验收返修、回执丢失、依赖集成、轻量修复；自由模拟还包含用户决策、额度阻塞、代码变化、候选失败、配置与消息排队。

“重载视图”只演示从内存记录恢复视图和核对请求。真实浏览器刷新仍清空原型；没有磁盘 journal、真实运行器回执或进程崩溃验证。旧 A–D 状态不迁移到 E。

尚未实现：Herdr 原生组件、真实 Agent 对话、实际源码与文件附件、真实预览、tracker 写回、自动运行器能力查询、真实持久化和跨进程故障恢复。HTML 原型用于确认交互和操作约束，不能替代真实接入验收。

## v0.4 原型变化

默认从原工作台进入；加入普通 Space 与重复目录入口，以及停用、暂停回执、重新启用核对、目录失效和汇总提醒的内存演练。旧五条流程继续保留。所有目录、暂停和恢复核对仍是模拟，不代表真实 Herdr 接入。

新增流程经无头 Comet 实际点击验证：普通 Space 不显示对话入口；后台问题只更新汇总；重复目录定位原入口；停用等待暂停确认；恢复核对后继续同一运行。另核对新工作区启用不切布局、取消停用、旧验收失效与自然收尾完成。六个引导演练通过，1440 与 390 像素视口无横向溢出，浏览器无运行异常。以上均为内存模拟验证。
